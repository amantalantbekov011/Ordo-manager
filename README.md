# ORDO Manager

Современный корпоративный портал ORDO для директора и ассистента: обзор рабочего дня, задачи, календарь, встречи, поручения, сотрудники и контроль доступности.

## Возможности

- авторизация с ролями директора и ассистента;
- Dashboard с показателями, прогрессом, ближайшими событиями и статусом ассистента;
- создание, изменение, удаление, фильтрация и смена статуса задач;
- месячный календарь задач и событий;
- встречи, звонки, поездки, места и участники;
- отдельный реестр поручений;
- справочник сотрудников и контактов;
- адаптивный интерфейс для компьютера и телефона;
- журнал действий на сервере, безопасные cookies и хеширование паролей;
- health-check и конфигурация Render Blueprint;
- интеграционные тесты основных API-сценариев.

## Локальный запуск

Требуется Node.js 20 или новее. В проекте нет внешних npm-зависимостей.

```bash
npm start
```

Открыть: <http://localhost:3000>

Локальные демонстрационные учётные записи:

- `aman` / `1234` — ассистент;
- `director` / `1234` — директор.

Пароли `1234` нельзя использовать в публичной версии.

Проверки:

```bash
npm run check
npm test
```

## Развёртывание на Render

Репозиторий содержит `render.yaml`. В панели Render нужно создать новый Blueprint, подключить приватный GitHub-репозиторий и перед первым запуском задать секретные переменные:

- `DIRECTOR_PASSWORD` — пароль директора;
- `ASSISTANT_PASSWORD` — пароль ассистента.

Конфигурация создаёт Node.js Web Service, health-check `/health` и постоянный диск `/var/data`. Файл базы задаётся переменной `DATA_FILE=/var/data/db.json`, поэтому данные сохраняются после повторного развёртывания.

Для текущей рабочей версии необходим платный сервис Render с persistent disk. Следующий производственный этап — перенос данных с JSON-файла в управляемую PostgreSQL.

```text

  index.html
  styles.css
  app.js

data/               локальные данные (не попадают в Git)
docs/               архитектурные решения
materials/          исходные архивы и референсы
server.js           HTTP-сервер и REST API
render.yaml         конфигурация Render
```

Архитектурное решение и дальнейшая схема хранения описаны в `docs/ARCHITECTURE.md`.
