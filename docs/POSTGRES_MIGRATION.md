# Безопасная миграция ORDO Manager на PostgreSQL

## Текущее состояние

Пока `DATABASE_URL` не задан, production продолжает использовать постоянный файл `/var/data/db.json`. Этот режим совместим с текущим Render-сервисом и не требует платных ресурсов.

## Автоматическая миграция

После появления `DATABASE_URL` сервер при запуске:

1. создаёт таблицы `ordo_state` и `ordo_state_backups`, если их ещё нет;
2. читает существующий `/var/data/db.json`, не изменяя и не удаляя его;
3. добавляет отсутствующие `createdAt` и `updatedAt`;
4. записывает состояние в PostgreSQL одной транзакционно-безопасной операцией `UPSERT`;
5. повторно читает состояние из PostgreSQL и сверяет версию и количество записей во всех основных коллекциях;
6. создаёт снимок `verified-initial-import`;
7. запускает приложение только после успешной проверки.

Если проверка не пройдена, health-check отвечает ошибкой, deploy не становится рабочим, а исходный JSON остаётся без изменений.

## Откат

Для отката достаточно убрать `DATABASE_URL` и перезапустить предыдущий или текущий commit. Сервер снова откроет сохранённый `/var/data/db.json`. До отдельного подтверждения успешной эксплуатации PostgreSQL файл и диск Render удалять нельзя.

## Резервные копии

Приложение создаёт ежедневный снимок в `ordo_state_backups` и сохраняет последние 30 снимков. После покупки базы дополнительно следует включить независимые штатные backups Render, поскольку снимок внутри той же базы не заменяет внешнюю аварийную копию.
